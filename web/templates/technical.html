Architecture & Engineering

This lexicon isn't just a static JSON file; it is powered by a set of advanced string-matching algorithms specifically designed to handle the complexities of the Khmer script.

1. The Aho-Corasick Automaton

Searching a document for 5,700 terms using a naive loop requires 5,700 passes over the text. The Checker class instead builds an Aho-Corasick automaton at startup. This algorithm constructs a finite state machine that allows it to find every occurrence of all 5,700 terms in a single, simultaneous pass over the document. The cost scales with the length of the document, not the size of the dictionary.

2. Boundary Detection in Spaceless Text

Khmer is written without spaces between words. This makes naive substring matching dangerous. For example, finding ប្រក (a valid term) inside the word ប្រកាស ("announce") is an error.

The Checker applies a two-tier filter to prevent this:

  • Grapheme Clusters (UAX #29): Every match must start and end on a Unicode grapheme cluster boundary to avoid splitting a syllable in half.
  • CRF Tokenizer: The match must also align perfectly with the word boundaries predicted by khmer-nltk's Conditional Random Field segmenter.

Finally, a longest-match-wins rule ensures that compound terms like ក្រុមប្រឹក្សាធម្មនុញ្ញ are reported once, rather than as three overlapping nested terms.

3. Typo-Tolerant Deletion Index

Because typing Khmer correctly is challenging, an exact-match dictionary often fails users. The Dictionary class implements a typo-tolerant search using a "deletion index".

Instead of calculating the Levenshtein distance against all 5,700 terms at query time (which is too slow), it pre-computes every possible single-cluster deletion for every term at startup. A near-match is thus reduced to a rapid dictionary lookup, returning suggestions that are exactly one grapheme cluster away.
