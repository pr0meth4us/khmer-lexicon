1 The pipeline

Nothing below runs when you use the site. It runs once per build; the site loads the finished file.

  1. Collect the source documents

    Terminology bulletins, glossaries and lexicons published by the National Council of Khmer Language, the Royal Academy of Cambodia, the Council of Ministers, the Ministry of Post and Telecommunications and the Royal Government. Each PDF's SHA-256 is recorded, so any entry can be traced to the exact file that was read. Seven were recovered from Wayback Machine captures of the NCKL's previous website, because the council's own download links are dead.

    sources.json · candidates.json · scripts/verify_sources.py

  2. Read every page with OCR

    Each page is rendered to an image and read by Google Cloud Vision. Text layers inside the PDFs are not trusted: several use legacy Khmer fonts whose characters map to the wrong Unicode.

    scripts/extract_*.py · OCR text cached per page

  3. Structure the OCR text into entries

    A language model (Gemini) turns each page's OCR text into fields: Khmer headword, English, French, part of speech, definition, examples. It is given text only, never the page image — shown images, it invented titles that were not on the page. The instructions forbid correcting or translating anything.

    scripts/extract_new_sources.py

  4. Clean and normalise

    Item numbers and gloss markers (អ., បារ.) are stripped. Characters from other scripts that look like Khmer are repaired, marks are put into canonical order — which Unicode's own normalisation cannot do for Khmer — and a subscript ro typed in the wrong order is fixed.

    khmerlex/normalize.py · khmerlex/contamination.py

  5. Merge and de-duplicate

    An entry with the same Khmer and English as one already present is not added again. Ids are stable: new sources are appended after the existing entries. The recovered documents yielded 2,697 entries, of which 768 were new; most of the rest were terms first published in earlier bulletins.

    scripts/merge_new_sources.py

  6. Validate, or fail the build

    Every build counts its detectable defects — empty fields, duplicates, characters out of range, implausibly long or short terms — and fails if any count is worse than the committed baseline. It then stamps a content-addressed build id, so the same data always has the same id.

    scripts/validate_lexicon.py · dist/quality_baseline.json · dist/manifest.json

  7. Measure accuracy against the printed page

    A seeded random sample of entries is checked, character by character, against crops of the source page. See §5.

    scripts/evaluate_sample.py · EVALUATION.md

  8. Publish

    The code, reports, provenance and a 309-entry sample go to GitHub and are archived on Zenodo with a DOI. The full lexicon is loaded by this site from private storage and reached through search and the API. A TBX export exists for terminology tools.

    scripts/export_tbx.py · CITATION.cff

2 NLP methods

Khmer is a low-resource language with a script that breaks many assumptions built into text tools. These are the methods each step relies on, and why the obvious alternative fails for Khmer.

Script and encoding

Grapheme clusters (UAX #29)
Khmer is an abugida: a syllable is a base consonant plus subscript consonants joined by COENG and vowel marks, several code points drawn as one unit. ក្រសួង is 6 code points but 3 clusters. Every length, slice, edit distance and match boundary in this project is measured in clusters, never code points.

khmerlex/graphemes.py

Canonical mark ordering
Unicode normalisation (NFC) cannot unify Khmer typed in different mark orders: only 2 of the block's 114 characters have a non-zero combining class, so NFC treats everything else as already ordered. The same word can then be byte-different forever. A Khmer-specific reordering fixes it at build time.

khmerlex/normalize.py

Script contamination and confusables (UTS #39)
A Devanagari or Thai vowel sign can sit inside a Khmer word, invisible on screen, and the word stops matching anything. Same-letter pairs across Brahmic scripts are derived from Unicode character names (195 pairs), visual lookalikes from the Unicode confusables data.

khmerlex/contamination.py

Extraction

OCR
Google Cloud Vision reads rendered page images. The PDFs' own text layers are not used: legacy Khmer fonts map glyphs to the wrong Unicode, and ្ត and ្ដ are encoded as one mis-mapped glyph.

scripts/extract_new_sources.py

LLM information extraction
A language model maps unstructured OCR text onto a fixed schema (headword, glosses, part of speech, definition, examples): slot filling, with instructions to copy and never correct. It sees text only, because with page images it hallucinated titles. One prompt per page layout: a prompt tuned for gloss-led glossaries shifted definitions onto the wrong entries in numbered tables.

PROMPT_NUMBERED · PROMPT_GLOSS

Output verification
Each extracted headword is checked against the OCR text it came from, anchored at the start of a line, with line wraps and item numbers allowed. This catches a model dropping a character the OCR read correctly, which a plain substring test cannot see.

verify_against_ocr()

Building the lexical resource

Near-duplicate detection
A symmetric-deletion index (the idea behind SymSpell) finds every pair of forms one cluster apart without comparing all pairs. Levenshtein distance over clusters then confirms each pair, and a shared English gloss separates spelling variants from different words.

scripts/find_near_duplicates.py

Character confusion model
How often people actually confuse two Khmer characters, aggregated from 3.2M searches (seanghay/khmer-character-confusions). This turns "these look similar" into a measured likelihood that a difference is a misread.

data/khmer-character-confusions.csv

Validation against a reference dictionary
Errors that turn one real word into another are found by comparison with the Royal Academy's 2022 dictionary (38,694 headwords). Absence proves nothing, because glossaries coin new terms. The test is narrower: one plausible cluster substitution away from a dictionary word, with compounds split into dictionary headwords and skipped first.

scripts/check_against_rac.py

Evaluation

Stratified sampling and weighted estimation
A seeded sample with a per-source floor, so small sources are covered. Each source is weighted by its true size when combining, so the floor does not bias the overall rate.

scripts/evaluate_sample.py

Wilson score intervals
Error rates are reported as intervals, not point estimates. The Wilson interval stays valid near 0% and with small samples, where the normal approximation gives impossible or overconfident ranges.

wilson()

Annotation guidelines and error typology
Judged against what the page printed, not what is correct. Errors are classed (dropped vowel or subscript, truncation at a wrap, dropped second form, substituted letter) so each can be traced to OCR or extraction. Inter-annotator agreement is not yet measured: one annotator.

EVALUATION.md

Using the lexicon

Word segmentation
Khmer writes no spaces between words. A conditional random field segmenter (khmer-nltk) supplies word boundaries, so a term found inside a longer unrelated word — ប្រក inside ប្រកាស — is rejected.

khmerlex/checker.py

Multi-pattern matching (Aho–Corasick)
Every term is found in a draft in one pass, at a cost that depends on the draft's length, not the lexicon's size. Measured: below about 220 terms a naive loop is faster.

khmerlex/aho.py

Typo-tolerant and phonetic retrieval
A query with no exact match gets entries one cluster away, from the same deletion index. A deliberately lossy Latin search key lets someone who knows a word by sound find it: "tinnany" reaches ទិន្នន័យ.

khmerlex/dictionary.py · khmerlex/romanize.py

Terminology interchange (TBX)
Exported as TBX-Basic (ISO 30042:2019), one concept per entry with Khmer, English and French sections and concept-level provenance, for termbases and computer-assisted translation tools.

scripts/export_tbx.py

Data statement
Documentation in the schema of Bender & Friedman (2018), so anyone training or evaluating on the data knows its variety, provenance and limits. See §4.

4 Data statement

Summarised from the full statement, which follows Bender & Friedman (2018), Data Statements for NLP. Read DATA_STATEMENT.md →

Curation rationale
Government bodies publish the approved Khmer forms of technical, legal and policy terms as scanned PDFs. The aim is to make them checkable rather than guessed. Documents, not words, were selected: every term in a chosen document is included, apart from exact repeats, Bulletin No. 2's word-formation tables (a grammar exercise), and 18 entries that were empty or plainly broken.
Language variety
Standard written Khmer (km, ISO 639-3 khm) in the formal register of government publication, often neologisms coined by the issuing body. English and French are glosses, present where the source was bilingual or trilingual.
Authorship
Institutional; individual committee members are not named in the sources.

None added. Part of speech, category and definition are transcriptions of what the documents printed, inconsistencies included: the pos field mixes Khmer abbreviations, English labels and French gender markers.

5 Evaluation

Automatic checks find empty fields and stray characters. They cannot see the error that matters most: an OCR misread that turns one real Khmer word into another. Only the printed page can show that, so the entries were sampled and checked against it.

Method

  • Sample. Stratified random sample across sources, seed {{ v10.sample_seed }}, fixed before any row was checked.
  • Judged against what the document printed, not what is correct: a ministry's own typo reproduced faithfully counts as right. Any difference in characters — one vowel, one subscript — counts as wrong.
  • Checked on crops of the headword's cell at 300 dpi, zoomed to 600–700 dpi wherever a mark was in doubt, with code points compared when a word looked right but would not match.
  • Scored with Wilson 95% intervals, each source weighted by its true size so that small sources don't distort the total.
  • Excluded by design: entries containing ្ត or ្ដ, which print identically and cannot be judged by eye. They are listed for checking against the Chuon Nath dictionary instead.

  • Nothing about missing terms. A term the OCR dropped never reaches the data, so it can never be sampled.

7 Access, licence, citation

Access

The full dataset is not published. Search it on this site, or look terms up through the API, which has no bulk endpoint and no pagination. The GitHub repository carries the code, the reports, the provenance and a 309-entry sample. For research that needs the whole dataset, ask.

Licence

CC BY-SA 4.0. The licence covers the compilation: the pipeline, normalisation and merge rules, provenance and the arrangement of entries. The terms themselves were published by Cambodian government bodies and are not claimed. When a term's official status matters, cite the originating document.
