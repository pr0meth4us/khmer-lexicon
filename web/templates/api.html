API

{{ '{:,}'.format(about.entries) }} official Cambodian government terms, from 15 published sources, as JSON. No key, no account, CORS open to any origin. Read-only.

This exists because a website makes the data readable by people, and an API makes it usable by every other Khmer-language tool — spellcheckers, keyboards, translation memories, government systems. If you build something with it, attribution to the source ministries is requested.

Base URL /api/v1

Search

Khmer or English. Spelling is forgiven: if nothing matches exactly you get suggestions — entries one Khmer syllable away.

GET /api/v1/search?q=blockchain
GET /api/v1/search?q=ទិន្នន័យ&limit=10

One term, every sense

A Khmer form defined by several ministries returns several senses. Returns 404 with suggestions if it isn't found.

GET /api/v1/term?khmer=អភិបាលកិច្ច

Check a draft

Returns the official terms used with their positions, English loanwords that have an approved Khmer form, and characters that aren't Khmer. Positions are code-point offsets, guaranteed to fall on grapheme-cluster boundaries so a highlight never splits a syllable.

POST /api/v1/check
Content-Type: application/json

{ "text": "រដ្ឋាភិបាលបានអនុម័តគោលនយោបាយ digital transformation។" }

8,000 character limit.

Limits, stated plainly

  • 60 requests per minute per IP. Over that you get 429.
  • 100 results maximum per request, 40 by default.
  • There is no bulk endpoint, and this is not scrape-proof. The entire lexicon is a single public JSON file in the repository — that is deliberate, and cloning it is faster for you than paging through this API. The limits exist so one caller can't degrade the service for everyone, not to keep the data in.
